## Exact client / wire contract (director decision)

DriveClient(*,port:int,token:str,timeout:float=5.0). Host always127.0.0.1, HTTP only; port nonbool int1..65535, timeout positive finite int/float nonbool, token visible ASCII chars33..126 length32..256. Reject invalid constructor arguments before network. Never retain a live connection between calls; new http.client.HTTPConnection per call, no proxies/redirect following/environment transport config. Store token privately repr=False or custom safe repr, no logging/exceptions leaking token. Socket timeout is an inactivity/operation budget, NOT a guaranteed total deadline; document no syscall/network hard-cancellation guarantee. No unbounded automatic retries.

Methods (four public operations, constructor aside):
- list(source_id,file_id='root',*,limit=20,offset=0,name_contains=None)->dict
- find(source_id,file_id='root',*,name_contains:str,limit=20,max_entries=2000,max_depth=4)->dict
- read(source_id,file_id,*,offset=0,length=262144)->ReadReply
- save(source_id,file_id,data:bytes,*,overwrite=False,create_parents=True)->dict

For list/find/read send POST /v1/list|find|read with UTF8 JSON controls and Content-Type:application/json, Content-Length exactly, Authorization:Bearer <token>, Connection:close. source_id/file_id are configured alias/canonical FileRef ID, never host root. List/find use the exact keys above; read uses offset/length. Save sends POST /v1/save?<urlencoded source_id,file_id,overwrite=true|false,create_parents=true|false> with raw bytes body and Content-Type:application/octet-stream. URL encoding via urllib.parse.urlencode; never put credentials in query. No extra aliases, server-local path translation or source mapping.

Client validation before network: source_id nonempty str<=64ASCII identifier[A-Za-z0-9_-]; file_id nonempty str (root or canonical p/relative POSIX, no empty/dot/dotdot/backslash/NUL segments; save/read require nonroot). Source-ID validation is convenience, not an authorization boundary. limit nonbool int1..100; offset nonbool int>=0 (read offset+length<=2**63-1); read length int1..1048576; find max_entries int1..100000 and max_depth int0..64; name_contains None or str<=256 for list, required nonempty str<=256 for find; save data exact bytes length<=1048576, flags exact bool. Constructor/type failures TypeError, valid-type out-of-range ValueError. No filesystem lookups. Do not import a second filesystem resolver; this client merely validates lexical wire fields, server adapter handles containment.

Success HTTP200:
- JSON operations use {"ok":true,"result":{...}}. Return result dict without inventing metadata. Server list result intended {items,next_offset}; find {items,truncated,reason,inspected,skipped}; save {ref,bytes_written,parents_may_have_been_created}. Nested field completeness validated by server tests later; client validates envelope/result object and bounded body.
- read content type application/octet-stream; required decimal headers X-Drive-Offset, X-Drive-Observed-Size, X-Drive-Observed-Mtime-Ns and X-Drive-EOF-Observed true|false. Frozen ReadReply(data:bytes,offset:int,observed_size:int,observed_mtime_ns:int,eof_observed:bool). Bytes<=requested length, offset must match request, metadata nonnegative; initial metadata/EOF are observations, not stable file versions. Response may be shorter than requested only if eof_observed=True. Exact filled window with eof_observed=True is protocol-invalid per no-lookahead range contract. Don't enforce observed_size>=offset+len(data): growth may legitimately violate stale initial size.

Errors: DriveClientError with safe fields code:str,outcome_uncertain:bool,retry_safe:bool; str/repr contains fixed local text/code only, not remote message, bearer/root/body. Recognize fixed codes invalid/denied/not_found/exists/too_large/busy/unavailable/timeout from error envelope {"ok":false,"error":{"code":...,"outcome_uncertain":bool,"retry_safe":bool}} on non200; unknown/malformed reply maps unavailable. Honor uncertainty if returned; save transport/protocol/timeout failures conservatively outcome_uncertain=True,retry_safe=False (even if no publish actually happened). Read-only transport errors uncertaintyFalse,retry_safeTrue. Never retry save or imply verify-then-retry is race-safe. Local validation failures before any network are TypeError/ValueError as above.

Bound replies while reading: JSON/control/error bodies<=65536bytes; binary<=requested length<=1MiB. Read at most cap+1 to detect excess, not unbounded response.read(). A declared Content-Length above cap fails before body read; missing/chunked responses still bounded. Always close response/connection on success/error/partial failure. Don't follow redirects. On wrong MIME/missing/invalid/duplicate observation headers fail closed. Do not expose server exception text.
